# PayPal sandbox: ручные сценарии

Откройте эту папку как отдельную коллекцию, выберите **Private**. Нужны запущенные сервисы и PAYPAL_CLIENT_ID/PAYPAL_CLIENT_SECRET sandbox. Настройте PAYPAL_RETURN_URL и PAYPAL_CANCEL_URL с `/api/v1/orders/payment/return` и `/api/v1/orders/payment/cancel`.

Перед запуском создайте тестового администратора через `pnpm admin:create` из корня проекта, задав `ADMIN_EMAIL`, `ADMIN_NAME`, `ADMIN_PASSWORD` (для Docker см. [инструкцию проекта](../README.md#авторизация)). Автоматического администратора больше нет.

Скопируйте `environments/Local.bru` в `environments/Private.bru` и заполните в копии `email` и `password` созданного администратора. При необходимости измените `baseUrl`. `Private.bru` исключён из Git; шаблон `Local.bru` не содержит реквизитов. Не сохраняйте пароли в отслеживаемых файлах.

Не запускайте всю коллекцию Runner: между запросами требуется действие покупателя, а доставка и возврат — альтернативные ветки.

1. Выполните `01 Prepare` по порядку. Внимание: очищается корзина администратора; используйте тестовую учётную запись.
2. Выполните `02 Payment / Start payment`. Откройте approveUrl из ответа в браузере и подтвердите покупку sandbox-аккаунтом покупателя.
3. Выполните остальные запросы `02 Payment`. Если return callback уже захватил платёж, capture должен идемпотентно вернуть PAID.
4. Выберите одну ветку: `03 Shipping` для PAID → SHIPPED → DELIVERED либо `04 Refund alternative` для отмены оплаченного заказа и возврата. Для второй ветки создайте и оплатите новый заказ, повторив Prepare и Payment. Не выполняйте Refund после Shipping.
5. Выполните `05 Cleanup` после выбранной ветки. Для доставленного заказа остаток останется списанным; товар будет удалён.

При отсутствии PayPal конфигурации Start payment должен завершиться ошибкой сервиса; позитивный тест останется красным. Эти запросы прошли проверку синтаксиса парсером Bruno, но реальные платежи в рамках подготовки коллекции не выполнялись.
