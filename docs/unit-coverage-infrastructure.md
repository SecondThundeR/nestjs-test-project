# Инфраструктурные исключения из unit-покрытия

В [списке исключений](../test/unit-coverage-infrastructure.txt) перечислены конкретные файлы. Прикладная логика Orders и Products, в том числе решение о резерве, компенсация, платёжный адаптер, RPC-контроллеры и CQRS-обработчики, входит в порог 100% по всем четырём метрикам.

| Исключённые файлы | Автоматическая проверка |
| --- | --- |
| `apps/orders/src/main.ts`, `orders.module.ts` и `apps/products/src/main.ts`, `products.module.ts` | [Сквозной заказ](../test/e2e/orders.e2e-spec.ts) запускает собранные приложения и проводит запросы через Gateway, TCP, CQRS, базу и кэш. [HTTP-контракты](../test/e2e/gateway-contracts.e2e-spec.ts) проверяют маршруты и сериализацию на собранном стеке. |
| `apps/{orders,products}/src/data-source.ts` и содержимое `src/migrations/` | [Тесты миграций](../test/migrations.integration-spec.ts) берут штатные списки миграций и метаданные из исходных DataSource, применяют миграции PostgreSQL на чистой схеме и проверяют обновление базы с отменённым заказом. |
| `apps/orders/src/entities/` | [Восстановление заказа](../apps/orders/test/stock-recovery.integration-spec.ts) записывает и читает заказы, намерения резерва и незавершённые операции на схеме, созданной штатными миграциями. |
| `apps/products/src/entities/` | [Резерв на PostgreSQL](../apps/products/test/stock.integration-spec.ts) проверяет журнал и обновление остатков. [Проверка Redis](../apps/products/test/stock-cache.integration-spec.ts) проверяет чтение и запись через реальный ProductsModule. |
| `apps/{auth,users}/src/main.ts`, `auth.module.ts`, `users.module.ts` | [HTTP-контракты Gateway](../test/e2e/gateway-contracts.e2e-spec.ts) проходят через собранные Auth и Users при регистрации, входе, чтении профиля и завершении сессии. |
| `apps/{auth,users}/src/data-source.ts` и содержимое `src/migrations/` | [Тесты миграций](../test/migrations.integration-spec.ts) используют штатные конфигурации Auth и Users, применяют миграции на чистой PostgreSQL и проверяют обновление существующих пользователей. |
| `apps/auth/src/entities/session.entity.ts` и `apps/users/src/entities/user.entity.ts` | [Ротация сессий](../apps/auth/test/session-rotation.integration-spec.ts) проверяет запись и обновление SessionEntity на мигрированной PostgreSQL. [HTTP-контракты](../test/e2e/gateway-contracts.e2e-spec.ts) сохраняют пользователя и читают его через собранный Users. |
| `apps/cart/src/main.ts`, `cart.module.ts` и `schemas/cart.schema.ts` | [Сквозной заказ](../test/e2e/orders.e2e-spec.ts) и [Kafka → SSE](../test/e2e/cart-events.e2e-spec.ts) используют собранный Cart. [Конкурентные записи](../apps/cart/test/cart-concurrency.integration-spec.ts) читают сохранённый документ через схему Cart на MongoDB версии проекта. |
| `apps/users/src/scripts/create-admin.cli.ts` | [Скрипт E2E](../test/e2e/run.sh) запускает собранную CLI на мигрированной БД Users. Следующий [HTTP-сценарий](../test/e2e/gateway-contracts.e2e-spec.ts) входит с созданной учётной записью и выполняет административные операции. |
| `apps/gateway/src/main.ts` и `gateway.module.ts` | [HTTP-контракты](../test/e2e/gateway-contracts.e2e-spec.ts) проверяют собранный Gateway, версионированные маршруты, guards и оба OpenAPI-документа. [Kafka → SSE](../test/e2e/cart-events.e2e-spec.ts) проверяет запуск Kafka-транспорта и доставку событий. Правило фильтрации документа каталога проверяется в [unit-тестах OpenAPI](../apps/gateway/src/common/openapi.unit.spec.ts). |
| `libs/cache/src/cache.module.ts` | [Проверка Redis](../apps/products/test/stock-cache.integration-spec.ts) запускает ProductsModule, получает настроенный кэш через DI и проверяет состояние записей в Redis. |

Обработчики и контроллеры декорированы через Nest. Vite/Oxc генерирует условные выражения для метаданных типов импортированных зависимостей. Конфигурация V8 исключает эту форму сгенерированного выражения из подсчёта веток. Сборку и внедрение зависимостей проверяет полный E2E-стек.
