# Граница 100% unit-покрытия

Для всей прикладной логики проекта принимаем целевое unit-покрытие 100% по строкам, веткам, функциям и инструкциям, включая файлы, которые ни один тест не импортировал. Область покрытия определяется поведением кода, поэтому правило валидации в DTO или решение в адаптере входят в неё наравне с правилом в сервисе.

Для каждого инфраструктурного исключения указываем, какая проверка обнаружит его поломку. Например, штатные миграции применяем к пустой PostgreSQL, а сборку модулей и запуск приложения проверяем на собранном сервисе. Так unit-набор остаётся быстрым, а инфраструктурное поведение проверяется в среде, где оно проявляется.
