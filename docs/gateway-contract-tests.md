# HTTP-контракты Gateway

Коллекции [Bruno](../bruno/README.md) и [PayPal Sandbox](../bruno-paypal/README.md) доступны для ручных прогонов. Здесь перечислены гарантии, которые они проверяют на публичном API, и соответствующие автоматические проверки.

| Контракт и набор Bruno | Гарантия | Автоматическая проверка |
| --- | --- | --- |
| Setup, Authentication | Health доступен публично. Регистрация создаёт обычного пользователя и скрывает хеш пароля. Некорректный ввод и подмена роли отвергаются. Дубликат email, неверные реквизиты, ротация refresh и logout проверяются отдельно от формы DTO. | [HTTP-сценарий Gateway](../test/e2e/gateway-contracts.e2e-spec.ts), [таблицы DTO](../libs/domains/src/http-requests.unit.spec.ts), [тесты Auth](../apps/auth/src/auth.service.spec.ts), [конкурентная ротация](../apps/auth/test/session-rotation.integration-spec.ts), [тесты Users](../apps/users/src/users.service.spec.ts) |
| Access control | Все защищённые маршруты возвращают 401 без токена и с повреждённым токеном. Четыре административные операции возвращают 403 для обычного пользователя. | [HTTP-сценарий Gateway](../test/e2e/gateway-contracts.e2e-spec.ts) |
| Products, Cleanup | Каталог доступен публично, изменение и удаление доступны администратору. DTO проверяют типы, ограничения цены и остатка, неизвестные поля и пустой PATCH. Отсутствующий товар даёт 404, изменение отражается при следующем чтении из кэша. | [HTTP-сценарий Gateway](../test/e2e/gateway-contracts.e2e-spec.ts), [таблицы DTO](../libs/domains/src/http-requests.unit.spec.ts), [тесты Products](../apps/products/src/products.service.spec.ts), [Redis](../apps/products/test/stock-cache.integration-spec.ts) |
| Cart | Корзина изолирована по владельцу. Добавление, объединение, изменение, удаление и очистка учитывают наличие товара и остаток. Ноль при изменении удаляет позицию. Конкурентные записи сохраняются. | [HTTP-сценарий Gateway](../test/e2e/gateway-contracts.e2e-spec.ts), [таблицы DTO](../libs/domains/src/http-requests.unit.spec.ts), [тесты Cart](../apps/cart/src/cart.service.spec.ts), [MongoDB](../apps/cart/test/cart-concurrency.integration-spec.ts) |
| Orders | Контракт описывает форму успешных ответов и ошибок. Список ограничен владельцем. Чужие чтение, отмена, запуск оплаты и capture возвращают 404. Администратор может менять статус в пределах разрешённых переходов. Ошибка резерва даёт 400, повторная отмена возвращает остаток один раз. | [Orders OpenAPI](../apps/gateway/src/orders/orders.openapi.yaml), [проверка OpenAPI](../apps/gateway/test/orders.contract.integration-spec.ts), [HTTP-сценарий Gateway](../test/e2e/gateway-contracts.e2e-spec.ts), [тесты Orders](../apps/orders/src/orders.service.spec.ts), [резерв и отмена через Gateway](../test/e2e/orders.e2e-spec.ts) |
| Платёжные callback и PayPal Sandbox | Callback доступны без JWT. Return проверяет токен оплаты, cancel возвращает подтверждение. Фактическое подтверждение покупателем, доставка и возврат проверяются через Sandbox. | [Тесты callback](../apps/gateway/src/orders/orders-payment.gateway.controller.spec.ts), [проверка OpenAPI](../apps/gateway/test/orders.contract.integration-spec.ts), [инструкция Sandbox](../bruno-paypal/README.md) |
| SSE и завершение сессии | Событие получает владелец, logout закрывает только поток отозванной сессии. | [Kafka → SSE через Gateway](../test/e2e/cart-events.e2e-spec.ts) |

Таблицы DTO проверяют варианты входных данных. HTTP-сценарий проверяет фактический статус и тело ошибки, а также подключение guards. Тесты сервисов проверяют правила операций с валидным входом, например превышение доступного остатка. Для запуска проверок Gateway отдельно используйте `pnpm run test:e2e gateway-contracts`.
